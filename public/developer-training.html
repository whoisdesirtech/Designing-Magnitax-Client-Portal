Welcome aboard · Developer Onboarding

Developing the Magnitax Secure Client Portal

This guide gets you set up and productive on the Magnitax Portal — a single-page web app for tax clients and CPA admins, built with vanilla HTML/CSS/JS on Firebase Hosting, Firestore, Storage, and Auth. Read it once, and you'll be able to run the project, make changes safely, and ship.

Repo: Designing-Magnitax-Client-Portal Live: taxagentai062026.web.app Audience: Developers Version 1.0

For admins: this guide pairs with the admin training that covers granting GitHub and Firebase access.

Welcome & Orientation

What this project is and how it's built

The Magnitax Portal is a zero-framework single-page application:

LayerTechnologyPurpose
Frontend Vanilla HTML5, CSS3, ES6+ JS No build step — open the page, it just runs
Design system CSS variables + glassmorphism Magnitax Emerald theme (#10b981 / #059669)
Auth Firebase Auth (email/password) Client vs CPA Admin roles
Data Cloud Firestore Users, intakes, documents, leads, audit logs
Files Firebase Storage Private W-2 / 1099 / Form 1040 PDFs
Hosting Firebase Hosting Global CDN at taxagentai062026.web.app

Important: there is no framework and no build step. What you edit is what deploys. Be careful and test locally before pushing.

Environment Setup

Confirm your machine is ready

Prerequisites

  • Node.js v18 or newer and npm.
  • Git, with your identity configured.
  • A Google account added to the Firebase project by an admin.

Verify Your Environment

Terminal
node -v
npm -v
git --version
git config user.name
git config user.email

Commit identity is required. GitHub rejects commits with no user.name / user.email. Set it once:

Terminal
git config --global user.name "Your Name"
git config --global user.email you@example.com

Clone & Run Locally

Get the code and launch the portal on your machine

The repo is github.com/whoisdesirtech/Designing-Magnitax-Client-Portal. The deployable app lives in the public/ folder.

Terminal
git clone https://github.com/whoisdesirtech/Designing-Magnitax-Client-Portal.git
cd Designing-Magnitax-Client-Portal/public
npx serve .
# Portal opens at http://localhost:3000 (or similar)

Test logins: admin@magnitax.com / Password123! (CPA Admin) or jane@example.com / Password123! (Client). Any 6-digit code passes the 2FA gate in this prototype.

Firebase CLI & Login

Connect your machine to the live project

Install the CLI (no global install needed) and sign in with the Google account your admin added to the project:

Terminal
npx -y firebase-tools@latest login
# A browser opens — sign in with the Google account added to the project
npx -y firebase-tools@latest use taxagentai062026
# Now using project taxagentai062026

Keep your CLI session private. Don't share machines or tokens. If you get Command requires authentication, re-run firebase login.

Your Daily Workflow

Branch → commit → pull request → merge

Never commit directly to main. Every change goes through a feature branch and a reviewed pull request:

Terminal — feature branch workflow
git checkout main
git pull origin main
git checkout -b feature/jf-fix-login-error
# ... edit files under public/ ...
git add .
git commit -m "feat: describe the change"
git push origin feature/jf-fix-login-error

Then open a Pull Request from your branch into main on GitHub. An admin reviews and merges it. Keep PRs small and focused, and describe what you changed and why.

Commit Message Style

  • feat: new feature or page
  • fix: bug fix
  • style: styling / theme alignment
  • chore: housekeeping (gitignore, config)
  • docs: documentation / training

Deploying to Production

Shipping merged work to the live site

Deploys run from a clean main after your PR is merged. Only deploy work that has been reviewed.

Terminal — deploy to Firebase Hosting
git checkout main
git pull origin main
npx -y firebase-tools@latest deploy --only hosting --project taxagentai062026

Production is instant. A bad deploy is visible to real tax clients immediately. Always test locally (Section 4) first. If something goes wrong, the admin can roll back from Firebase Console → Hosting → Release history.

Rules & Security

Non-negotiable, applies to every developer
  • No secrets in code. Never commit API keys, service-account JSON, or passwords. Firebase SDK config keys are public by design; private keys are not.
  • No client data in logs or chats. Don't paste real W-2s, 1099s, PII, or screenshots of client records anywhere outside the app.
  • Never push to main. Work in branches; merge via pull requests.
  • Test locally before opening a PR. The portal must boot and core flows (login, 2FA, documents) must work.
  • Match the design system. Use the Emerald CSS variables (--accent, --bg-primary, etc.) — don't hardcode ad-hoc colors.
  • Keep .firebase/ and .env out of git. They are ignored for a reason.

Troubleshooting & FAQ

Common problems you'll hit
SymptomCauseFix
git push rejected (403) Invitation not accepted, or wrong GitHub account Accept the invitation; ask the admin to re-send to your correct account
Command requires authentication Firebase CLI not logged in (or logged into the wrong account) Run npx -y firebase-tools@latest login with the account added to the project
No Firebase project 'taxagentai062026' Your account isn't a member of the project Ask the admin to add you with the Editor role, then re-run firebase login
Login loop / wrong project Selected a different project with firebase use Run npx -y firebase-tools@latest use taxagentai062026
Changes don't appear after deploy Browser cache, or edits made outside public/ Hard-refresh; confirm the files are under public/ and committed
Can't read Firestore documents You're Viewer (read-only) instead of Editor Ask the admin to upgrade your role
